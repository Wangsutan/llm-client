# 内存监控并发优化记录（2026-11-04）

> 问题：对话与内存监控不能同时进行——聊天流式期间 `/mem.html` 的 `/api/mem` 轮询全部超时。

## 一、根因

板子主循环的 `WebServer` 是同步单线程：`webHandle()` = `server.handleClient()` 在主循环串行处理请求。
`/api/chat` 流式期间主循环被阻塞 30–40 秒，80 端口的 `/api/mem` 请求无法被处理（实测对话中
`/api/mem` 全部 TIMEOUT，而 81 端口正常）。

## 二、优化

1. **独立监控端口（81）+ 独立 FreeRTOS 任务**（`mem_monitor.cpp`）：
   - `WiFiServer(81)` 在单独任务里循环处理请求，只响应 `GET /api/mem`（直接返回 `memGetJson()`）；
   - 不碰文件系统（避免与主任务并发访问 LittleFS）；
   - 响应带 `Access-Control-Allow-Origin: *`，页面可从 80 端口跨端口请求；
   - 任务栈 8 KB，优先级 1。
2. **页面（`web/mem.html`）**：优先请求 `//<host>:81/api/mem`，失败回退同源 `/api/mem`；
3. **外网代理（`tools/esp32chat-proxy/proxy.py`）**：`/api/mem` 路径转发到板子 81 端口
   （新增 `MEM_PORT` 环境变量，默认 81），其余照旧转发 80。

## 三、验证

| 场景 | 结果 |
|---|---|
| 对话进行中直连 81 `/api/mem` | **200，0.03s** 持续响应（多次采样全部 200） |
| 对话进行中直连 80 `/api/mem`（对照） | TIMEOUT（主循环阻塞，证实原问题） |
| 外网 `203.0.113.10:8090/api/mem`（经 proxy 转发 81） | 200，返回真实 JSON |
| headless 打开 `/mem.html` | 页面请求 `http://<ip>:81/api/mem`，实时数值更新、canvas 绘制正常 |

对话与内存监控现在可以同时进行。

## 五、外网访问说明（2026-11-04 补）

- 外网经 `http://203.0.113.10:8090/` 访问时（页面端口 8090）：
  页面不再尝试 `<公网>:81`（未映射会卡住），而是**直接同源请求 `/api/mem`**，
  由 `proxy.py` 转发到板子 81 端口；浏览器在加载页面时已完成 Basic 认证，
  同源请求会自动携带凭据（实测：401 → 200 后，`/api/mem` 全部 200）；
- 局域网直连（无端口/80）：先试 81 端口（2.5s 超时），失败回退同源 `/api/mem`；
- 此前"外网没看到数据"的原因：页面先请求公网 `:81`（不可达）且没有超时控制，页面卡住；
  已修复并验证（外网 Playwright Firefox + httpCredentials：页面数据正常刷新）。

## 六、未动

- 主服务器 80 的 `/api/mem` 保留（非对话时可用）；
- 监控任务只读 `memGetJson()`（memprobe 全局状态），不写文件、不阻塞主循环。
