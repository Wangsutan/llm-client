# 内存监控真实版记录（2026-11-04）

> 需求：把"演示用"的内存占用网页变成**真实的堆叠图**——随时间变动、能实时展示、
> 也能回放最近一次对话的数据。

## 一、实现

### 固件侧

1. **memprobe 采样记录**：新增 `MemSamplePoint`（name / ms / free / maxAlloc / stackLeft），
   环形数组 `MEM_SAMPLE_MAX = 16`：
   - `memBegin()`：清空记录、记起点时间与初始采样点；
   - `memSample()`：记录每个阶段采样点；
   - `memEnd()`：记录 `end` 点；
2. **`memGetJson()`**：输出实时值（`total` / `free` / `minFree` / `maxAlloc` / `stackLeft` / `active`）
   与最近一次请求的 `samples` 数组；`minFree` 未初始化时用当前 `free` 兜底；
3. **`GET /api/mem`**：`web_api.cpp` 的 `handleMem()`，`web_server.cpp` 注册路由。

### 前端侧

- **`web/mem.html`**（打包进 LittleFS，`web_static.cpp` 的 `handleMemPage()` 提供）：
  - Canvas **堆叠图**：ROM/BT（64,348）、.data（25,413）、.bss（84,336）、堆已用、堆空闲
    （口径与旧演示一致：DRAM 335,872 / 堆段 161,784），每列一个时间点；
  - **实时模式**：每 0.8s 轮询 `/api/mem`，右侧追加列、窗口滚动（最多 90 列），
    数值面板显示 free / 本轮最低 / 最大连续块 / 栈剩余 / 堆已用；
  - **回放模式**：点「发起真实对话并回放」→ 页面发真实 `/api/chat` 请求 → 读 `/api/mem`
    的 `samples` → 按采样点逐列动画回放 + 下方阶段表（阶段名/时间/数值）。

访问方式：`http://<板子IP>/mem.html`（局域网、外网代理均可）。

## 二、验证（真实数据）

- 一次真实对话产生 **16 个采样点**：
  `upload → uploaded → parsed → chunk_begin → pre_connect → tcp_up → head_sent → req_sent →
  resp_head(34.1s) → first_delta → stream_end(39.1s) → upstream_closed → llm_done →
  done_written → resp_end → released`，free 在 139,820–151,172 之间真实波动；
- headless 验证：实时模式 canvas 已绘制、数值面板更新；回放模式表格 16 行、
  状态「回放完成 · 共 16 个采样点」；`/api/mem` 初始 `minFree` 兜底为 free（非 0）。

## 三、回放改为只读 + 数值千分位（2026-11-04 补）

- **回放只读**：不再发起真实对话（避免每次回放消耗一次模型调用、污染会话记录），
  回放模式直接读取 `/api/mem` 中最近一次请求的采样序列并播放；
  无数据时提示「请先在聊天页发一条消息，再回来回放」；
- **数值千分位**：所有字节值显示加英文逗号（如 `142,120`），
  面板与阶段表统一用 `fmt()` 格式化（毫秒也加千分位）。

验证（headless）：
- 实时模式面板显示 `142,120` 形式；回放模式自动回放 16 个采样点、表格数值带逗号；
- 回放全程**没有**任何 `/api/chat` 请求（只读回放）。

## 十四、两图横坐标对齐与滚动修复（2026-11-04 补）

- 问题一：主图与堆图列宽计算不一致（主图 `cw` 上限 10、堆图上限 12），横坐标没有严格对应；
- 问题二：列宽按 60 列计算，90 列时右侧列被画到画布外，看起来"到最右侧后不滚动"；
- 修复：固定列宽 `CW = canvas 宽 / 90 * 0.92`（`GAP = CW * 0.08`），**两图共用同一 CW/GAP
  与 `x = i*(CW+GAP)+1` 公式**，横坐标严格对应；列数满 90 后 `push` + `shift`，图形立即左移滚动；
- 验证：两 canvas 宽均 900、均正常绘制；90 列总宽约 894px，恰好落在画布内（不再溢出）。

## 十六、修复：条形不显示（2026-11-04 补）

- 问题：图中只剩「本轮最低 free」虚线，所有堆叠条形不显示；
- 根因：列宽常量 `CW = W / MAXCOL * 0.92` 定义在 `var MAXCOL = 90;` **之前**
  （`var` 提升，此时 `MAXCOL` 为 `undefined`）→ `CW = NaN` → 所有条形 x 坐标 NaN，
  canvas 忽略绘制；虚线不依赖 CW，所以正常显示；
- 修复：把 `CW`/`GAP` 定义移到 `MAXCOL` 之后；
- 验证：两图条形恢复（主图橙 1,038 / 浅黄 6,653 像素；堆图橙 1,485 / 浅黄 9,418 像素）。

## 十八、修复：最低 free 线被柱状图超过（2026-11-04 补）

- 问题：部分柱子的堆已用顶部超过「本轮最低 free」虚线；
- 根因：实时模式下 `minFree` 可能滞后于当前 `free`（两次采样之间 free 继续下降），
  线按 `minFree` 画、柱子按当前 `free` 画，于是柱子"超过"线；且上一轮的历史列混在已显示列中；
- 修复：
  1. 线值取 **min(本轮采样最低 minFree, 所有已显示列的 free 最低值)**——线永不超过任何柱子；
  2. **新一轮对话开始**（`/api/mem` 的 `active` false→true）时清空历史列，
     最低 free 线从新值重新画起（满足"新一轮对话从新得到这个值和线"）；
- 验证（headless 像素分析）：主图线 y=84 vs 堆已用顶 y=86（不超线，ok），
  堆专用图线 y=120 vs 121（ok）；回放 16 个采样点正常。
