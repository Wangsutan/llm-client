# 前端中英文切换记录（2026-11-03）

> 起因：用户要求前端加中英文切换，默认跟随浏览器语言、英文兜底；设置项放在设置弹窗
> 的「后端（大模型切换）」之前。

## 一、实现

- **文案字典**：`app.js` 顶部 `I18N = { zh: {...}, en: {...} }`，覆盖静态与动态文案：
  - 静态（`data-i18n` / `data-i18n-placeholder` / `data-i18n-title`）：标题、新建会话、发送、
    输入框占位符、会话列表/侧栏标题、设置面板（语言/后端/模型/取消/保存并生效/后端选项）；
  - 动态（`t()` 调用）：会话计数、新会话默认标题、正在回答/正在压缩历史、错误前缀、请求失败、
    空回答、已中止、历史过长提示、复制/已复制/没有可复制内容/已复制代码/下载/已开始下载、
    配置读取失败/已保存/保存失败；
- **默认语言**：`pickLang()` 优先级 = `localStorage('esp32-chat-lang')` → `navigator.language`
  以 `zh` 开头取中文 → 其余一律英文（兜底）；
- **切换**：设置弹窗新增「语言」下拉（位于「后端」之前），`change` 时立即生效
  （`applyI18n()` + `renderCurrent()` 重绘动态消息文案）并写入 localStorage；
- **初始化**：`loadState(); applyI18n();`，首屏即按当前语言渲染。

## 二、修复记录（两个坑）

1. **局部变量遮蔽全局 `t()`**：`renderConvList()` 内原有一个 `const t = document.createElement('span')`
   （会话标题元素），与新增的翻译函数 `t()` 同名，导致 `TypeError: t is not a function`
   （侧栏渲染时抛错）。修复：局部变量改名 `titleEl`。
2. **批量替换误伤字典**：给 JS 做文案替换时，纯字符串替换把 `I18N.zh.historyTooLong` 的值
   也改成了 `t('historyTooLong')`，造成初始化期访问未初始化的 `I18N`（TDZ：
   `Cannot access 'I18N' before initialization`）。修复：字典值恢复为原始中文串；教训是
   文案替换要带上下文（如 `botMsg.textContent = '错误: ' + msg` 这种完整表达式），不要
   替换裸字符串。

## 三、验证（headless Chromium，.88 打开 http://192.168.1.50/）

| 场景 | 结果 |
|---|---|
| 浏览器语言 en-US | 默认英文：title「ESP32 Chat」、按钮「New chat / Send」、占位符英文 |
| 浏览器语言 zh-CN | 默认中文：title「ESP32 聊天」 |
| 设置弹窗顺序 | 「语言」在「后端」之前（`compareDocumentPosition` 验证） |
| 切换 zh | 界面立即中文，localStorage 保存 `zh` |
| 切换 en | 界面立即英文，localStorage 保存 `en`；动态按钮文案「Copy」 |
| 中文下复制按钮 | 「复制」 |

无失败请求、无 console/page 错误。
