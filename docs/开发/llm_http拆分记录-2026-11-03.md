# llm_http 模块拆分记录（2026-11-03）

> 起因：`llm_http.cpp` 到 274 行时混着三类职责 —— 协议解析（Ollama JSON 行 / OpenAI SSE 行 /
> 鉴权头值）、公共 HTTP 流程（建连、分块发送、读流、收尾）、后端描述符实例。
> 用户批准只拆协议层，其余保持。
>
> 结论：**行为不变的纯文件搬移**，协议解析逻辑逐字未变。

## 一、拆分后布局

| 文件 | 职责 | 行数（拆分前 → 后） |
|---|---|---|
| `llm_http.h` | `BackendSpec` 结构 + `llmBackendSpec()` / `backendStream()`（未动） | 31 → 31 |
| `llm_http.cpp` | 描述符实例 + 公共流程（keepPrefix / streamEndName / ClientGuard / streamImpl / prepareSecure / backendStream） | 274 → 224 |
| `llm_protocol.h`（新增） | 协议差异声明：`ollamaParseLine` / `openaiParseLine` / `openaiAuthValue` | 9 |
| `llm_protocol.cpp`（新增） | 两个流式行解析 + Bearer 头值（从 llm_http.cpp 原样搬出，去掉 static） | 52 |

## 二、共享方式

- 描述符 `kOllamaSpec` / `kOpenaiSpec` 仍定义在 `llm_http.cpp`，`parseStreamLine` / `authValue`
  指向 `llm_protocol.h` 声明的函数；
- 协议解析纯函数只依赖 `ArduinoJson` 与 `secrets.h`（`OPENAI_API_KEY`），与传输层完全解耦；
- `llm_http.h`（对外接口与 `BackendSpec`）未改动。

## 三、行为不变清单

- `ollamaParseLine` / `openaiParseLine` / `openaiAuthValue` 逐字未变（含 `openaiParseLine` 里
  函数内 `static JsonDocument filter` 的单次构建）；
- 描述符字段（含 `.name` / `.tls` / `.streamIdleMs`）与拆分前一致；
- 公共流程一行未动。

## 四、验证

- **编译**：通过（esp32 core 3.3.12，default 分区）；固件 1,100,516 → 1,101,260 B（+744 B，
  多一个编译单元），globals 109,744 B 不变；arduino-cli 显示 84%。
- **格式化**：`clang-format --dry-run` 0 差异。
- **烧录回归**（板子 IP `192.168.1.50`，`.21` 串口抓 IP + curl，10/10 通过）：
  静态页、marked.min.js、config、models、chat（gzip/明文）、summarize、空 message 400、
  坏 JSON 400，串口日志 `[http] stream end: normal`。
