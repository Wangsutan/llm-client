## 一、重复代码的账（重构前）

`ollama_client.cpp`(209 行) 与 `openai_client.cpp`(232 行) 之间 **166 行逐字相同**（≈38%），
其中最大的几块：

| 块 | 位置 | 行数 |
|---|---|---|
| `buildMessages()` + 两行复制粘贴的注释 | 15–29 / 40–54 | 18 |
| 非流式请求体 + 发送 + 计时 | 37–65 / 65–93 | 19 |
| 非流式响应解析 + 回答封顶 | 66–80 / 94–106 | 15 |
| 分块发送 messages（`sendMsg` lambda 等） | 106–148 / 141–179 | 44 |
| 流式回调骨架 + 收尾 | 161–204 / 196–232 | ~28 |
| 其余零散（建连、头、读响应） | — | ~42 |

复制粘贴已经出过事：`memSample("first_delta")` 在两份里的顺序不一致（一份在 `shouldStop` 前、
一份在后），流式 idle 超时 300 s / 60 s 也不一致且无注释；历史上"流式丢字""断开即停"
等修复都是同一处改两遍。

其它系统性重复：`web_server.cpp` 15 处重复 `Cache-Control: no-store`、6 处手写 error JSON。

## 二、这次做了什么（两个提交）

### `828e4c1` 抽请求体管线 + 响应小工具

- 新增 `payload.h/.cpp`：upload 回调、gzip 头/尾解析、tinfl 解压、48 KB 静态工作区、
  零拷贝解析全部搬出 `web_server.cpp`（410 → 229 行）；
- 新增 `sendJson()` / `sendError()`：收敛 15 处 no-store 与 6 处手写 error JSON；
- 413 / 400 的文案与顺序、gzip/明文两条路径、静态分配方式**都没变**。

### `342fd0d` 统一两个后端

- 新增 `llm_http.h/.cpp`：`BackendSpec` 描述一个后端（地址、路径、鉴权头、是否 TLS、
  三处超时、`parseStreamLine` / `extractChatAnswer` 两个协议回调），
  建连/请求头/分块发送/读响应/逐行回调/收尾只写一份；
- 明文与 TLS 客户端都派生自 `NetworkClient`，公共实现吃基类引用；TLS 对象在调用点才构造
  （它一构造就占约 2.2 KB ssl 上下文，明文路径不该付这份钱 —— 这点是实测发现的，见下）；
- 删除 `ollama_client.*` / `openai_client.*`。

## 六、串口模式改走流式（同日，用户批准后）

- 删除非流式入口：`backendChat()` / `chatImpl()` / `buildMessages()`、`extractChatAnswer` 回调、
  描述符里的 `chatConnectMs` / `chatTotalMs` 两个超时字段；`llmChat()` 从公共 API 移除；
- `llm-client.ino` 的串口分支改成 `llmStream(..., [](const String &d) { Serial.print(d); })`，
  边收边打印；失败时打印 `[http] request failed`；
- `llm_http.cpp` 356 → 237 行（`.h` 39 → 31 行），C++ 总量 1,475 → 1,412 行；
- 固件 1,135,104 → 1,130,224 B（−4,880 B）；
- 消灭的隐患：非流式的 `http.getString()` 会把整份响应读进堆（上限 64 KB），
  串口问答从此和网页共用同一条"只留 2 KB 前缀 + 边收边转发"的路径。

| 网页 gzip / 明文 / 摘要 / 413 / DeepSeek | 5/5 通过 |
