# 移动端键盘遮挡修复记录（2026-11-03）

> 问题：移动端弹出输入法后，底部输入框被键盘遮挡，输入一点文字后才"弹上来"。

## 一、原因分析

1. `viewport` 没有声明键盘行为（`interactive-widget`），Android Chrome 默认只缩小视觉视口、不重排页面；
2. 页面高度用 `100dvh`，iOS Safari 键盘弹出时 `dvh` 不缩小（键盘是覆盖层），布局仍是整屏；
3. `body { overflow: hidden }` 阻止页面滚动，输入框无法被滚进可视区；
4. 输入文字后浏览器自动把焦点元素滚入可视区（`scrollIntoView` 行为），所以"输入一点文字才弹上来"。

## 二、修复（三处组合，覆盖 iOS / Android）

1. **viewport meta**：加 `interactive-widget=resizes-content`（Android Chrome/Edge 108+：
   键盘弹起时收缩 layout viewport，页面直接适配）；
2. **visualViewport 适配**（iOS 及兜底）：`app.js` 新增 `fitViewport()`——取
   `Math.min(window.innerHeight, visualViewport.height)` 写入 CSS 变量 `--app-h`，监听
   `visualViewport` 的 `resize`/`scroll`、`window` 的 `resize`/`orientationchange`；
   `html` / `body` / `.sidebar` / `.main`（含移动端 media query）的高度统一改为
   `var(--app-h, 100dvh)`（桌面无 `--app-h` 时回退 100dvh，行为不变）；
3. **聚焦滚动**：`#q` 聚焦后 300ms（等键盘动画结束）执行
   `scrollIntoView({ block: 'nearest' })`，确保输入框在可视区内。

## 三、验证（headless Chromium，400×800 模拟手机）

| 场景 | 结果 |
|---|---|
| 初始（800 高） | `--app-h:800px`，main 高 800，输入框 bottom 790（可见） |
| 模拟键盘（视口缩到 500 高） | `--app-h:500px`，main 高 500，**`#bar` bottom 500、输入框 bottom 490，均在可视区内** |
| 恢复（800 高） | `--app-h:800px`，布局还原 |

## 四、追加修复：点击复制按钮时输入法抖动（2026-11-03 晚）

- **现象**：移动端点击消息的「复制」按钮，软键盘抖动/闪烁。
- **原因**：http 环境走 `fallbackCopy()`，它创建 `<textarea>` 并 `select()`——select 会聚焦元素，
  移动端聚焦文本框会弹软键盘；随后移除 textarea 键盘又收起 → 抖动。
- **修复**：
  1. `fallbackCopy()` 改为 **Range 选中屏幕外隐藏元素**再 `execCommand('copy')`，不移动焦点、
     不唤起软键盘；仅当 Range 复制失败时才退回只读 textarea 兜底；
  2. 复制/下载按钮加 `mousedown` `preventDefault()`——点击时不抢输入框焦点，软键盘保持打开不收起。
- **验证**（headless，400px 移动视口）：先聚焦输入框（模拟正在输入），点击复制按钮后
  `document.activeElement` 仍为输入框、无残留 textarea、toast 正常显示。

## 五、未动
